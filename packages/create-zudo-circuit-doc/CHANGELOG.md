# Changelog

All notable changes to `create-zudo-circuit-doc` are documented in this file.

The format is based on Keep a Changelog, and release notes are generated from the changelog MDX pages.

## [0.2.3] - 2026-11-12

Version 0.2.3 generates projects on the zudo-doc 10.0.3 / ZFB 6.0.1 family and pairs them with
@takazudo/zudo-circuit-doc `^0.4.0`. Projects generated by
earlier versions are unchanged; to move one, follow the
0.3 to 0.4 migration recipe.

## Other changes

- Generated projects select runtime `^0.4.0` and pin zudo-doc and zudo-doc-history-server
  10.0.3 and ZFB, zfb-runtime and zfb-md-wasm 6.0.1.
- Follow create-zudo-doc 10's generator for the doc host: `typescript ^7.0.2` and
  `diff ^8.0.4 || ^9.0.0`. Graphite stays the generated look.

## [0.2.2] - 2026-11-12

Version 0.2.2 generates the same project as [0.2.1](#021---2026-11-07) apart from the runtime range.

## Other changes

- Generated projects select @takazudo/zudo-circuit-doc
  `^0.3.1`.
- Publish from the tag-triggered GitHub Actions workflow through npm Trusted Publishing (GitHub
  OIDC). No npm token is stored, and the package carries npm provenance that links the tarball to
  its release tag and commit.

## [0.2.1] - 2026-11-07

Version 0.2.1 generates projects on zudo-doc 9.1.4 and switches new projects to Graphite,
zudo-doc 9's default look. The runtime pairing is unchanged: generated projects still select
@takazudo/zudo-circuit-doc `^0.3.0` and ZFB 5.2.2.

## Features

- Generate `themePack: "graphite"` with `themePacks: ["graphite"]` in `doc/zfb.config.ts`, so
  new projects follow zudo-doc's current look in light and dark. The allowlist keeps the other
  bundled theme packs out of the build.
- Pin zudo-doc, zudo-doc-history-server and the vendored create-zudo-doc scaffold provenance to
  9.1.4. The upstream scaffold parity check passes with no host-file changes.

## Other changes

- Projects generated by 0.2.0 keep the Classic look (`themePack: "default"`). To adopt
  Graphite, follow the
  ownership and upgrades guide.

## [0.2.0] - 2026-11-07

Version 0.2.0 generates projects on the published zudo-doc 9.1.3 / ZFB 5.2.2 family together
with runtime @takazudo/zudo-circuit-doc 0.3.0, following the
[#156](https://github.com/Takazudo/zudo-circuit-doc/pull/156) migration.

## Breaking changes

- Require Node 24 LTS (`>=24 <25`), matching zudo-doc 7 and later. Node 22 and 25 are unsupported.
- Generate the zudo-doc 9.1.3 / ZFB 5.2.2 host and select runtime `^0.3.0`. The generated pins
  are zudo-doc/history/create-zudo-doc 9.1.3 and the aligned ZFB 5.2.2 tuple, matching the
  runtime peer floors `^9.1.3` / `^5.2.2`.

## Other changes

- Projects generated by 0.1.0 stay on runtime `^0.2.0` with zudo-doc 5 / ZFB 2 until their host
  migration is intentional; follow the
  existing-consumer migration recipe.
- Verify the scaffold against the published runtime with strict packed-consumer types, build,
  browser, and fixture checks.

## [0.1.0] - 2026-09-27

Initial release of `create-zudo-circuit-doc`, an initializer that creates a ready-to-use
circuit-development project with a zudo-doc site, the runtime package, canonical project workflows,
and evidence authoring templates.

## Features

- `pnpm create zudo-circuit-doc <destination>` scaffolds a project from a template kept in sync with
  the `examples/empty` host, checked for parity with the upstream zudo-doc scaffold.
- Generated projects depend on `@takazudo/zudo-circuit-doc` through a `^0.1.0` caret range and ship a
  `circuit.config.ts`, empty evidence data, the canonical agent workflow, skills, and authoring
  templates.
- Options: `--name`, `--title`, `--library`, `--agent claude|codex|both|none`, `--yes`,
  `--install` / `--no-install`, `--git` / `--no-git`, and `--runtime-spec` to override the runtime
  dependency with a semver range, dist-tag, or absolute `file:` spec.
- A non-empty destination is rejected and left byte-for-byte unchanged; an existing empty directory
  is accepted.
- Generated projects include a README titled after the site, a `contract.md`, and plain-text next
  steps.
