Neither `create-zudo-circuit-doc` nor `@takazudo/zudo-circuit-doc` is published on npm yet (see
[Release](../release/) for exactly what's free and what isn't). Until a release ships, try the
project from tarballs packed out of a checkout of this repository.

## 1. Pack both packages

From a checkout of [Takazudo/zudo-circuit-doc](https://github.com/Takazudo/zudo-circuit-doc),
with dependencies installed and the runtime package built:

```sh
corepack pnpm install
corepack pnpm --filter @takazudo/zudo-circuit-doc build
corepack pnpm --filter @takazudo/zudo-circuit-doc pack --pack-destination /tmp/zudo-circuit-doc-tarballs
corepack pnpm --filter create-zudo-circuit-doc build
corepack pnpm --filter create-zudo-circuit-doc pack --pack-destination /tmp/zudo-circuit-doc-tarballs
```

This produces `takazudo-zudo-circuit-doc-0.1.0.tgz` and `create-zudo-circuit-doc-0.1.0.tgz` in
`/tmp/zudo-circuit-doc-tarballs` (pick any scratch directory outside the repository).

## 2. Run the initializer from the tarball

Outside the monorepo, run the packed initializer directly with `pnpm dlx`, skipping its own
install for a moment:

```sh
pnpm dlx /tmp/zudo-circuit-doc-tarballs/create-zudo-circuit-doc-0.1.0.tgz my-circuit \
  --name my-circuit --title "My Circuit" --no-install --no-git
```

The initializer scaffolds `my-circuit/` with a real semver range,
`"@takazudo/zudo-circuit-doc": "^0.1.0"`, in **two** places — the root `package.json`
(`devDependencies`) and `doc/package.json` (`dependencies`, since the site itself imports the
package's islands and MDX components). Neither has anything to resolve against until a release is
published, so point both at the runtime tarball before installing:

```sh
cd my-circuit
sed -i 's#"@takazudo/zudo-circuit-doc": "\^0.1.0"#"@takazudo/zudo-circuit-doc": "file:/tmp/zudo-circuit-doc-tarballs/takazudo-zudo-circuit-doc-0.1.0.tgz"#' package.json doc/package.json
corepack pnpm install
```

`create-zudo-circuit-doc` itself takes:

```
create-zudo-circuit-doc [destination] [--name <npm-name>] [--title <site title>]
                         [--library <kicad-lib-name>] [--agent claude|codex|both|none]
                         [--yes] [--install|--no-install] [--git|--no-git]
```

| Flag | Default | Effect |
| --- | --- | --- |
| `--name <npm-name>` | the destination's basename | The generated `project.name` / `package.json` name |
| `--title <site title>` | title-cased `--name` | The generated `project.title` / site title |
| `--library <lib-name>` | `--name` | The KiCad library name written into `circuit.config.ts` (used only once CAD is enabled) |
| `--agent claude\|codex\|both\|none` | `both` | Which thin agent-entry file(s) to write: `CLAUDE.md`, `AGENTS.md`, or both |
| `--yes`, `-y` | off | Do not prompt; a missing destination becomes an error instead |
| `--install` / `--no-install` | install on | Run `pnpm install` after scaffolding |
| `--git` / `--no-git` | git on | Run `git init` plus an initial commit |

`--agent both` (the default) is what makes [Claude Code and Codex share one workflow](../workflows/agent-collaboration.mdx):
both `CLAUDE.md` and `AGENTS.md` are thin, near-identical pointers to the one canonical
`circuit/WORKFLOW.md`.

## 3. Confirm it worked

```sh
pnpm circuit:doctor
```

should print `node`, `config` and `python` as `ok`, and `docker`, `chrome` and `easyeda2kicad` as
`missing` (optional) unless you already have them — see
[The first run](./first-run.mdx).

Once a release is published, this whole page collapses to `pnpm create zudo-circuit-doc my-circuit`.
