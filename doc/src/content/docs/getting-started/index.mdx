`zudo-circuit-doc` is a circuit-development project initializer built on
[zudo-doc](https://github.com/zudolab/zudo-doc). It follows the same initializer/runtime split as
[zudo-sg](https://github.com/Takazudo/zudo-sg):

- **`create-zudo-circuit-doc`** — an initializer that generates a new project.
- **`@takazudo/zudo-circuit-doc`** — the runtime package a generated project depends on: the CLI,
  the MDX renderer and preview islands, and the canonical Python evidence validator.

Both packages sit on top of zudo-doc the same way zudo-sg does: the generated project is an
ordinary zudo-doc site (`doc/`), with `@takazudo/zudo-circuit-doc` adding one more kind of
content — component evidence — on top of zudo-doc's authored documentation. If you already know
zudo-doc or zudo-sg, the generated project's `doc/` directory, `zfb.config.ts` and header
navigation will look familiar; what's new is the `circuit/` directory and the `.claude/skills/`
evidence bundles described in [Concepts](../concepts/).

A generated project opens as useful documentation before it has any component, board, KiCad file
or firmware. It carries one canonical agent workflow, so a short request such as "download this
datasheet", "get the 3D model" or "check this spec" becomes durable, honest project knowledge:
exact identity, retained evidence, regenerated documentation and a truthful statement of what is
still unknown.
