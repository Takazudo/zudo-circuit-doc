## What was run (Claude Code variant)

Both steps used Claude Code 2.1.283 and the model `claude-opus-5-5`, with the same isolation flags:

```sh
env -u CLAUDE_ADDITIONAL_DIRECTORIES -u CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD \
    -u CLAUDECODE -u CLAUDE_CODE_CHILD_SESSION \
  claude -p "<prompt verbatim>" \
    --setting-sources project,local --strict-mcp-config --no-session-persistence \
    --session-id <new uuid> --model opus --output-format json --max-budget-usd 10 \
    <step-specific tool flags>
```

The flags keep the orchestrating session's user-level settings, hooks, MCP servers and extra
directories out of the child. As a result the child sees only the copy's own `CLAUDE.md`,
`.claude/skills/` and files. Neither step passed `--continue` or `--resume`.

## Grading key

This key comes from the committed bundle (`.claude/skills/component-ti-tmp1075dr/facts.json` and
`coverage.json`), not from a Codex answer. A future run passes only if all of the following hold.

**Continue passes when:**

- `pnpm circuit:check` and `pnpm check` both pass on the copy afterwards.
- The diff touches only project-owned files. The expected set is the owner bundle's
  `coverage.json` (and `facts.json` only if a fact changes),
  `doc/src/content/docs/project/next-actions.mdx`, and the generator's own
  `doc/src/content/docs/components/**` and `circuit/generated/preflight.json`. Nothing under
  `node_modules/`, and no second copy of the evidence anywhere.
- The note cites the facts that already exist: `fact-tmp1075-address-pin-strapping` (locator
  "Table 5-1 Pin Functions, rows A2, A1, A0") and `fact-tmp1075-address-all-gnd` (locator
  "Table 7-2 TMP1075 Address Pins State, row A2=0 A1=0 A0=0"), from sources `src-tmp1075-ds-pins` and
  `src-tmp1075-ds-address`. It introduces no new address value. Whether the breakout's actual strapping
  was verified is a board question, so any verdict about it stays `NEEDS BENCH` or remains an

## Re-running it

1. Pack the runtime and build the temporary copy the way `scripts/verify-pack.mjs` does in its
   minimal flow (`copyWithoutNodeModules`, then `installLocalTarball` for `package.json` and
   `doc/package.json`, plus a root `pnpm-workspace.yaml`). Put the copy under a fresh `mktemp -d`
   directory, so no parent `CLAUDE.md` is picked up. Run `pnpm install`, then `git init` and make a
   baseline commit. Run baseline `pnpm circuit:check` and `pnpm check`.
2. Run the two prompts above, verbatim, each in a brand-new process:
   - **Claude Code:** use the command in [What was run](#what-was-run-claude-code-variant). Continue
     adds `--permission-mode dontAsk` and the tool allowlist shown there. Query adds
     `--tools "Read,Glob,Grep"`. Give each a new `--session-id`.
   - **Codex:** `codex exec`. Continue uses `--sandbox workspace-write -C <copy>`; Query uses
     `--sandbox read-only -C <copy>`.
3. Grade the results against the key above. Validate with `pnpm circuit:check` and `pnpm check` run
   by you, not only by the agent. Read the diff with `git status` / `git diff` on the copy. For Query,
   compare `git status --porcelain --ignored` and file hashes before and after the run.
4. For Codex, reap any broker (`codex-sweep.js --workspace <copy>`). Delete the copy.
5. Replace this page's status and "What was run" table with the actual outcome. Record a failure as
   a failure, and never edit the key to make a run pass.
