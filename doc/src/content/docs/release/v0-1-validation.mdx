**Result: 29 of 31 acceptance scenarios pass through automated checks, and 2 are not run.**

- **AGENT-01 was not run**: the Codex CLI hit its account usage limit.
- **BENCH-01 was not run**: it needs physical hardware.
- **FACT-03 passes only as a limit test.** The actual catch is the human or agent review step in
  Workflow E, and the validator makes no claim of dimensional correctness.
- **No physical test of any kind ran.**

A passing schema, build or browser check shows that the evidence and the remaining work are visible
and consistent. It does not show that a circuit works.

Every result below comes from a run made for this report on 2026-09-26, on the merged base branch
(`base/circuit-doc-v0-1` at `3ebc428`, with #2–#33 merged). No result was copied from an earlier issue's
report. The raw run logs stay in the validation session's local log and are not committed. Each
command below can be run again to reproduce its result.

## Evidence by type

The five evidence types are listed separately below. A result of one type is never counted as a
result of another.

### Source inspection

- `test/scenarios/cad-02.test.ts` reads the three CAD receipts in M and its vendor README (CAD-02).
  `test_scenarios.py` lints `circuit/WORKFLOW.md` for its Workflow C and Workflow E sentences, and
  scans the validator source for any claim of dimensional verification (SRC-01, FACT-03).
- The M evidence bundle compares TI's D0008A example land pattern (1.55 × 0.6 mm pads, 5.4 mm row
  span) with the KiCad pads (1.95 × 0.6 mm) and records the difference as a fact. That comparison
  was made while the example was written ([#25](https://github.com/Takazudo/zudo-circuit-doc/issues/25),
  [#29](https://github.com/Takazudo/zudo-circuit-doc/issues/29)); it was **not** redone for this report.
- For this report: the AGENT-01 structural criteria (single evidence root, thin
  `CLAUDE.md`/`AGENTS.md` pair) were checked by inspection, and the licensing files were read.

### Automated checks

These are gates 1–5, 7, 8 and 9 above, and they carry every PASS in the scenario tables. None of them
goes online. Validator runs report `offline=True; refreshed=none`.

### Browser checks

- `check-browser` passed on the LED fixture site (gate 6, and again in G5c): 32 responsive and theme
  cases, footprint and model dialogs, on-demand idle, SPA dispose and remount, direct reload, no-JS
  fallback and a viewer-free catalog.
- `check-browser` passed on the packed minimal site (G5b, `M4`): 8 cases on the TMP1075DR record,
  including footprint dialog and WRL viewer hydration.
- **Not run: human visual review.** The `verify:pack --fixture minimal` run prints a reminder that a
  person should still read two things in context: the exact "shared footprint package" wording
  under the model viewer, and the `cad-assets` / `cad-physical-fit` coverage reasons.
  `check-browser` proves hydration, dialogs, geometry and theming, but not whether prose reads
  correctly. No person reviewed the pages for this report.

### CAD geometry checks

- `footprints check` compares the committed footprint previews with their inputs, and passed inside
  `pnpm check` for M (gate 3b) and in the packed consumer (G5b `CAD-DOCKER-MISSING`, run without
  Docker).
- The pin-asset check passed for M (`SCOPE: … pin-asset check performed`): the symbol's pins equal
  the footprint's pads.
- `derive.mjs --check` (CAD-02) and `check-cad-freshness.mjs` (CAD-03) passed.
- The reference check on the built L site covered 35 records, 25 footprint SVGs and 25 models.
- **Not re-run:** rendering footprint previews with the pinned Docker KiCad image. Physical fit is
  never checked by software here; `fact-tmp1075-cad-physical-fit` stays `NEEDS BENCH`.

### Physical hardware tests

**None ran.** No board has been built. Three facts in the evidence bundle stay `NEEDS BENCH`:
installed accuracy, self-heating, and CAD physical fit. See [BENCH-01](#bench-01).

**Not run.** The Codex CLI (codex-cli 0.156.1) returned its account usage-limit error on the first

## BENCH-01

**Not run: requires physical hardware.** Recording a bench result is covered by
[Workflow F](../workflows/index.mdx) in every generated project's `circuit/WORKFLOW.md`, together with
its verification template, `circuit/templates/project-docs/verification/bring-up.mdx`. Both files
ship in `examples/empty`, `examples/minimal` and the initializer's `templates/default`. The template
records board revision, population changes, firmware, instruments, setup, supply, load, ambient
conditions, method, raw observations, the criterion with its basis, and the outcome. A result recorded
with it is scoped to the tested unit and uses `BENCH-OBSERVED` provenance. Both files were reviewed;
neither can produce a result without a board.

### Known issues from the seed, and how they were closed

| Seed finding | Outcome |
| --- | --- |
| The full validator assumed the three lamp boards | Closed. Inventory providers (`manual` and `led-generator-v1`) take board names from configured specs ([#12](https://github.com/Takazudo/zudo-circuit-doc/issues/12), [#17](https://github.com/Takazudo/zudo-circuit-doc/issues/17)). |
| An empty `specs` fell back through `specs or (...)` | Closed. The fallback is removed, and specs come only from config (ADR-010). |
| Non-LCSC PCB inventory, and routing between same-named parts | Closed. The generic-v1 profile, plus manufacturer-first resolution (ADR-009, ADR-010; PART-02, PART-04). |
| `NOT APPLICABLE` on an unavailable source blocked | Closed. NOT APPLICABLE never blocks, with regression tests in both directions (ADR-008). |
| `COVERED` could include NEEDS BENCH | Closed as a UI truthfulness fix. The bench requirement stays visible (FACT-04), and COVERED is not redefined as physical verification. |
| Units were checked for presence, not for dimensional algebra | Kept as an explicit human or agent review step (Workflow E; FACT-03). There is deliberately no code fix. |
| Exact counts 25/35/91/8 and fixed scanner corpus limits | Closed. The counts are project-owned `expect.*` values in `selection.json` (0 allowed, ADR-012) and scanner policy in config ([#15](https://github.com/Takazudo/zudo-circuit-doc/issues/15), [#19](https://github.com/Takazudo/zudo-circuit-doc/issues/19)). |
| The route needed static preview-island imports | Kept as a tested seam: an islands seed plus a chrome-bindings shim (ADR-016). |
| Ownership of existing generated targets was not preflighted | Closed. Emit is plan → validate → write → remove, and any conflict changes zero bytes ([#10](https://github.com/Takazudo/zudo-circuit-doc/issues/10); OUT-01). |
| The SG version constant differed from the package version | Avoided. `--version` reads `package.json` at runtime (`VERSION-MATCH` in G5a). |

### Deferred items (not in v0.1)

- **Update and migration.** A generated project's authored content is create-only.
- **Manufacturing export profile.** There is no Gerber, pick-and-place or fabrication export.
- **Supplier acquisition helpers.** Nothing beyond the optional `easyeda2kicad` import for LCSC parts.
- **STEP viewer.** The preview stays WRL-only, and there is no general CAD converter.
- **Supplier-SKU alias routing.** Routing alias classes stay `mpn`, `lcsc`, `manufacturer` and
  `function`.
- **`.agents/skills` wiring for Codex.** Evidence stays in `.claude/skills/`, and Codex reaches it
  through `AGENTS.md` → `circuit/WORKFLOW.md`. No mirror is created.
