These are historical case studies from the [zudo-led-lamp](https://github.com/Takazudo/zudo-led-lamp)
project, at the pinned commit `194d8a297e3545588197342130c3111a66c10973`. They are examples of
reusable workflow behavior — not instructions to apply the lamp's electrical choices to a new
circuit — and the vendor data/CAD they reference has not been independently revalidated during
this epic's research. Every link below is a permalink to that pinned commit, so it stays valid
even as the lamp repository moves on.

## Lesson 1 — "Download 3D data" can reveal a wrong footprint

The selected ALPS RK10J11E0034 supplier record C470643 returned assets representing a shared
dual-unit family. The project documented the exact single-unit pin mapping and retained a
family-qualified model. The transferable result is not merely a downloaded file; it is a record
of what the import actually represents, which electrical pads were corrected and which geometry
remains approximate.
[Original case](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/footprints/vendor/C470643/README.md).

**Seed behavior:** obtain → inspect exact variant → correct or qualify → record provenance →
regenerate preview.

## Lesson 2 — A visually similar switch can have the wrong height

For G-Switch SS-12D01-G020 (C5446803), the source family model's actuator projection differed
from the selected variant. The repository retains the original source, a derivation script, the
corrected STEP/WRL pair and a dimensional audit. The derived model remains explicitly qualified;
geometry processing does not prove physical board seating.
[Source and derivation notes](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/footprints/vendor/C5446803/README.md),
[model audit](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/footprints/vendor/C5446803/model-audit.json).

**Seed behavior:** retain original bytes → retain deterministic transformation → compare
dimensions → keep physical fit as an open/observed result.

## Lesson 3 — "Check the spec" needs more than the source link

The evidence contract separates recommended operating limits, absolute maxima, typical curves
and transient/protection conditions. It also distinguishes primary evidence, calculated results,
project choices and bench observations. These dimensions have to survive the readable page.
[Contract](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/.claude/skills/component-spec-audit/references/contract.md).

**Seed behavior:** claim → exact document/locator → units and conditions → dependency check →
explicit verdict.

## Lesson 4 — Good individual components do not prove the whole circuit

The lamp's integration rules span source evidence, conditioned reasoning, generated design
state, pin/footprint mapping, PCB orientation, assembly exports, as-built state, programmed
state and bench work. Those stages answer different questions. A verified source or a clean
netlist does not close later physical questions.
[Integration rules](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/.claude/skills/circuit-spec-integration/references/rules.json).

**Seed behavior:** project-specific integration rules, added when a real interaction exists;
keep open stages visible.

## Lesson 5 — Documentation should derive from the knowledge records

The component engine already has a pure evidence-to-view-model projection and a deterministic
MDX emitter, separate from data-provider mechanics. Its adoption guide explicitly discusses
extraction. This is the most direct foundation for this project.
[Adoption guide](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/doc/src/content/docs/how-to/component-docs-adoption.mdx).

**Seed behavior:** one evidence record → agent-readable knowledge and human-readable docs;
authored pages supply rationale.

## Lesson 6 — Historical prose can outlive a conclusion

The lamp's design and next-steps pages reflect iterative research and corrections. Some prose
and inventory summary states lag more detailed evidence. Keep current decisions tied to current
fact/source IDs, and preserve past reasoning as history rather than an unqualified current claim.
[Next steps](https://github.com/Takazudo/zudo-led-lamp/blob/194d8a297e3545588197342130c3111a66c10973/doc/src/content/docs/architecture/next-steps.mdx).

**Seed behavior:** every consequential change updates the authoritative record and the current
decision/handoff together.

## Lesson 7 — Manufacturing is a snapshot of a design

The LED manufacturing archive ties exported artifacts and checks to source state, population
intent and rotation corrections. This is a useful later extension. It should not impose
JLCPCB, a personal converter or a lamp-specific board set on every new circuit.
[Manufacturing archive](https://github.com/Takazudo/zudo-led-lamp/tree/194d8a297e3545588197342130c3111a66c10973/manufacturing).

**Seed behavior:** optional provider with source revision, assembly population, raw and
transformed exports, checks and order state.
