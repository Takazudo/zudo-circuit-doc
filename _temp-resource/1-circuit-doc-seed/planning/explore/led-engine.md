## risks
- The seed says the emit gap is only static. It is now reproduced, and it is two bugs: (a) a marker-less target is silently overwritten (emit.ts:115-121); (b) prune runs after the writes (emit.ts:124), so a hand-authored stray file aborts only after pages were rewritten. Both must be fixed before the initializer ships a writable generated tree.
- The seed's hard-coded list is incomplete. It misses footprint-previews/generate.ts:129,:140 (25/35), scan-artifacts EXPECTED_WITHHELD=6 (:121), REQUIRED_AGENT_ROUTES/SECTION_PAGES (:152,:446), the LED INTEGRATION_DOMAIN_GLOSS in core (render/shared.ts:577-598), GENERATED_MARKER text (page.ts:26-27), check.ts:24-30 labels, evidence.ts:220/234 labels, model-assets MODEL_PUBLIC_ROOT, and the zld- CSS prefix. An implementer following only the seed will leave LED assumptions in.
- Shipping .ts from the runtime package fails at runtime (ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING). All Node-executed code (core, adapters, cli, footprint tools) must be compiled to JS. Tests inside the monorepo can keep running .ts sources with --experimental-strip-types, but a pack-and-install test must exercise dist JS.
- The CLIs execute on import (top-level await in generate/check/models; main().catch in scan-artifacts) and the footprint scripts guard on basename(process.argv[1]). A single package bin that imports them would run every command, and a compiled filename (.js) disables the footprint main guard. They must be refactored into exported functions before bin wiring.
- Changing GENERATED_MARKER text (it contains 'doc/component-docs' and 'pnpm generate:components') changes line 2 of every generated page. It also makes isGeneratedContents reject existing LED or consumer trees unless a legacy marker is accepted. Changing INTEGRATION_DOMAIN_GLOSS, routes or landing copy likewise changes LED golden bytes. Do path/config injection first with byte-identical goldens, then make copy/marker/version changes as separate reviewed golden updates.
- Bumping VIEW_MODEL_VERSION to 2 needs the ViewModelVersion literal type widened (view-model.ts:38); otherwise supportedViewModelVersions cannot list older versions. It also changes preflight.json and test literals. Do it after the LED regression fixture is green.
- The models CLI, footprint-previews selection and scan-artifacts call readEvidenceIndex() directly and skip both the Python validator and assertSelectionFresh (model-assets.ts:35, footprint-previews/selection.ts:7-8, scan-artifacts.ts:527-530). A consumer can therefore publish WRLs or SVGs from an unvalidated corpus unless these entry points go through the same validated path.
- An empty project still fails on: the references.ts:93 and model-assets.ts:37 exact-25 gates; the footprint 25/35 gates; scan-artifacts minimums (100 canaries/60 files/100/150) and positiveControls throwing when al8860mp-13 is absent; and the landing/integration links to /docs/claude/ and /docs/claude-skills/<owner>/, which links.ts does not check (links.ts:33, :72) and which 404 unless zudo-doc claudeResources is enabled in the scaffold's zfb.config.

- walkMdx only considers .mdx (emit.ts:201). Non-.mdx files placed in the generated root are neither pruned nor reported, so consumer images or other files dropped there persist silently. Document this or report it.
- fs.watch recursive watches only .json under the skills root (watch.ts:126-127). Once selection moves into project config/JSON, edits to selection or circuit.config.ts will not trigger regeneration unless those files are added to the watch set.
- Tests bound to host files (presentation.test.ts:31-32, model-viewer.test.ts:18-19) and to repo CI files (workflow-contract.test.ts) cannot move into packages/circuit-doc unchanged. They must follow the UI/islands extraction or be rewritten against the package's own bindings map and stylesheet.
