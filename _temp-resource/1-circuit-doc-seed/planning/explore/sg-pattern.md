# sg-pattern: zudo-sg packaging/initializer pattern (create-zudo-sg + @takazudo/zudo-sg engine, fixture->template sync, pack-and-install verifiers, PR CI) as the model for zudo-circuit-doc

## Summary
Inspected zudo-sg at HEAD b9b36ce (the same commit the seed pinned), read-only. The seed report sg-architecture.md is accurate on the CLI surface, the template transforms, the withZudoSg shape and the VERSION drift. It misses the mechanics a planner needs, and two of its recommendations conflict with the current task.

**Monorepo shape.**
- Root `package.json` is private, `"type": "module"`, `packageManager: "pnpm@11.5.2"`, with no engines field.
- `pnpm-workspace.yaml` lists `packages: [".", "packages/*", "apps/*", "doc"]`, `allowBuilds` (esbuild, lefthook, msw) and a name-only `minimumReleaseAgeExclude` list. It has no catalog.
- `fixtures/` is deliberately NOT a workspace member. `fixtures/engine-host` is its own pnpm root (`packages: []`) and depends on the engine through `"@takazudo/zudo-sg": "file:.tarball/zudo-sg-engine.tgz"` (`fixtures/engine-host/package.json:20`). So it only ever runs after being copied to os.tmpdir(), never in place.

**Build tooling per package.**
- `create-zudo-sg` builds with plain tsc into `dist/` (`package.json:44-49`, `tsconfig.json` with rootDir src). The bin is a 6-line JS shim, `bin/create-zudo-sg.js`, that imports `../dist/cli.js` and sets `process.exitCode`. The package has only an `exports["."]`, no `types`, and `files` = bin, dist, templates, `!dist/__tests__`, CHANGELOG.md.
- The engine builds with `tsup` (`bundle: false`, esm) followed by `tsc -p tsconfig.build.json` for declarations (`packages/styleguide/package.json:129`, `tsup.config.ts`). It has 30-odd `exports` with `types` listed before `default`, one bin, and only peerDependencies on zfb, zudo-doc, zdtp and preact. It has no `workspace:*` deps, so `pnpm pack` never has to rewrite a workspace protocol.

**CLI (`packages/create-zudo-sg/src/cli.ts`).**
- Uses `node:util` parseArgs with strict mode, plus alias normalisation.
- Accepts one positional directory, `--name`, `--install` / `--no-install` (last one wins), `--yes`, `--help`, `--version`.
- Without a directory it prompts on a TTY; `--yes` or a non-TTY session makes that an error.
- The package name defaults to the destination's basename and is validated against the npm grammar.
- It runs `scaffold()`, then `pnpm install` only when `--install` is given, then prints `Created X` and the next-step commands.

**Scaffolder (`src/scaffold.ts:157-203`).**
- Validates the name and the template dir, and reads the template's `package.json` before touching the target.
- Requires the target to be absent or an empty directory.
- Copies recursively, renaming `_gitignore` to `.gitignore` and preserving symlinks.
- Does a string `replaceAll` of `__PROJECT_NAME__` in `package.json` only.

**Template sync (`scripts/sync-create-zudo-sg-template.mjs`).**
- Builds the whole expected tree in memory from `fixtures/engine-host`.
- Skips node_modules, dist, .zfb-build, .zfb, .tarball, pnpm-lock.yaml and three zfb temp-file patterns (lines 58-70).
- Renames `.gitignore` to `_gitignore` and drops the `.tarball` and `pnpm-lock.yaml` lines from it.
- In `package.json`: `name` becomes `__PROJECT_NAME__`, `version` becomes `0.1.0`, and the engine dep becomes `^<engine version>`.
- In `zfb.config.ts`: rewrites `base: "/styleguide/"` to `"/"` and throws if that string is absent.
- Regenerates `minimumReleaseAgeExclude` as exact `name@version` pins. It takes these from the fixture's deps plus root `node_modules/@takazudo/zfb`'s optionalDependencies, and cross-checks the versions.
- `--check` diffs byte-for-byte and lists drifted paths. A write replaces the whole target with `rm -rf`.

**Verifiers.**
- Both pack via `corepack pnpm --filter <pkg> pack --pack-destination <mkdtemp>` from the repo root, and run the consumer in `mkdtemp(os.tmpdir())`.
- `verify-create-zudo-sg.mjs` then:
  1. extracts the initializer tarball and runs its bin with `--yes --no-install`;
  2. asserts the file set, `.gitignore` via git check-ignore, and the release-age pins;
  3. copies the engine tarball into `<host>/.tarball/` and rewrites the dep to `file:.tarball/<name>.tgz`, unless `--published-engine` is passed;
  4. runs `pnpm install`, then a `--frozen-lockfile` reinstall in a clean copy;
  5. runs the printed next steps, `tsc`, `zfb build` with DOM assertions, `check-links.mjs`, and a `zfb dev` boot on a free port.

  On CI the verify step takes about 22-28 s and the whole job about 40-45 s (runs 36041529994, 36034061721, 35973417915, 35966482431, 35966456184).
- A local `file:` tarball is not subject to the release-age check. pnpm 11.5.2 defaults to `minimum-release-age` 1440 minutes, `strict-dep-builds: true` and `block-exotic-subdeps: true` (corepack pnpm.mjs:120507, 120521, 120528). That default is why the generated `pnpm-workspace.yaml` needs `allowBuilds` and the exact first-party exclusions.

**Config composition.** `withZudoSg` (`packages/styleguide/src/config/index.ts:291-315`) is a pure data transform:
- appends the engine's plugin descriptors (bare-specifier names plus options) and collections after zudo-doc's;
- optionally injects header nav and a trigger into the `@takazudo/zudo-doc/plugins/routes` descriptor;
- declares node-free status at :4-8 and duplicates a zudo-doc constant at :26-31 so it can be imported without peers.

Host config for the CLI is `zudo-sg.config.mjs`, loaded by dynamic import from `process.cwd()` (`src/cli/config.ts:150-160`, `bin.ts:19`). There is no `--root` or `--config` flag.

**CI.** `.github/actions/setup` runs pnpm/action-setup v6.1.0 (version from `packageManager`), setup-node 24 and `pnpm install --frozen-lockfile`. PR checks do not cache the pnpm store; the publish workflows do (`cache: pnpm`). Each job checks out, runs setup, then runs one pnpm script. `concurrency` cancels superseded runs, and triggers are PRs to `main` and `base/**`.

**VERSION drift is confirmed.** `src/cli.ts:13` has `export const VERSION = "0.1.0"`, `package.json:3` has `"version": "0.1.8"`, and `--version` prints the constant (`cli.ts:170-173`). No test covers `--version`.

## risks
- pnpm 11 default minimum-release-age=1440 min: any freshly published first-party dep (zudo-doc, zfb, zfb platform binaries, and later @takazudo/zudo-circuit-doc itself) will fail install in generated projects unless the template's pnpm-workspace.yaml carries exact name@version minimumReleaseAgeExclude entries; zfb optional platform binaries each need their own entry.
- Local machine has strictDepBuilds:false in ~/.config/pnpm/config.yaml while CI uses pnpm 11 default strict-dep-builds:true — a verify run that passes locally can fail on CI if allowBuilds (esbuild etc.) is incomplete. Verifier should pass an explicit config or assert with CI-like settings.
- block-exotic-subdeps=true: if @takazudo/zudo-circuit-doc ever depends on another local package via workspace:* or file:, the packed tarball will carry a version that isn't published (or an exotic subdep) and the foreign install fails. Keep the runtime package free of workspace:* deps (peer-depend on zudo-doc/zfb like the SG engine does) or ensure pack rewrites to published versions.
- Circuit CLI requirement 'config passed explicitly (circuit.config.ts)': loading a .ts config from a Node CLI relies on Node type-stripping (unflagged only from Node 22.18 / 23.6; never for files under node_modules; no enums/namespaces). SG sidesteps this with zudo-sg.config.mjs. Either declare engines >=22.18 and restrict syntax, use .mjs, or load via a bundler (esbuild/tsx) — must be decided before writing the runtime CLI.
- SG CLI resolves project root from process.cwd() only (bin.ts:19) with no --root/--config; copying it verbatim would violate the 'root/config passed explicitly' requirement.
- Copying cli.ts verbatim reproduces the VERSION drift; derive from package.json at runtime (readFileSync(new URL('../package.json', import.meta.url))) and add a test asserting `--version` output equals package.json version.
- Aggregating package tests in a root vitest config forces the import.meta.url HTTP-URL fallback hack (scaffold.ts:21-37, cli.test.ts:13-17). Prefer per-package vitest (or vitest projects) so this hack is unnecessary.
- sync script requires root node_modules/@takazudo/zfb/package.json (ZFB_PACKAGE_PATH) — the circuit monorepo root must declare @takazudo/zfb as a dependency or the sync/check fails; CI codegen-drift job must run after install.
- If the circuit template fixture (fixtures/minimal) lives inside the workspace globs, its own pnpm-workspace.yaml would make it a nested workspace root; SG avoids this by excluding fixtures/ from pnpm-workspace packages and using file:.tarball deps. Mixing approaches (workspace:* in fixture) requires the sync to rewrite workspace:* -> ^version and to generate the template pnpm-workspace.yaml.
- tsc build in create-zudo-sg emits tests into dist/__tests__ and relies on files '!dist/__tests__' to exclude them; forgetting the negation in the copy leaks tests into the tarball.
- npm/pnpm pack drops .gitignore and .npmrc from tarballs — template must use _gitignore (and _npmrc if ever needed) and the verifier must assert the rename; any other dotfile in the template should be checked in the packed-template file-set comparison.
- Verifier depends on root devDeps jsdom (top-level import) and scripts/check-links.mjs; circuit monorepo must provide equivalents or drop those assertions.
